To connect your physical hardware to the FLOOD_ALERT (T.U.B.I.G.) web backend, the ESP32 must send structured data over HTTP/HTTPS. Below are the exact hardware configurations, endpoint configurations, and code payload structures required.1. Backend Server Endpoint ConfigurationIngestion Endpoint URL: [https://update-alarm--lloydeee10.replit.app/api/readings](https://update-alarm--lloydeee10.replit.app/api/readings) (or your local IP if testing locally, e.g., [http://192.168.](http://192.168.)x.x:3000/api/readings)HTTP Method: POST   Headers:Content-Type: application/json2. JSON Data Payload StructureThe ESP32 needs to package the sensor data into JSON before broadcasting. The payload must match the 0 to 4 status level mapping used by the system dashboard:JSON{
  "level": 2,
  "status": "Yellow",
  "latitude": 13.9416,
  "longitude": 121.1631,
  "battery": 88
}
Field Specifications:level (Integer, 0 to 4):0: Neutral / Safe (Green LED)1: Low Advisory (Blue LED)2: Warning (Yellow LED)3: High Risk (Orange / Yellow-Red LED)4: Severe / Evacuate (Red LED)status (String): "Green", "Blue", "Yellow", or "Red" (corresponds to your active LED state).latitude & longitude (Floats): Acquired directly from your GPS module (e.g., NEO-6M / TinyGPS++).   battery (Integer, Optional): Current battery percentage reading.3. Firmware Configuration Checklist (Arduino / ESP32 C++)Ensure these parameters are set inside your ESP32 sketch code:1.Cellular/GSM Setup (SIM800L):GPRS Network.Configure your APN settings based on your mobile carrier SIM card so the GSM modem can connect to the internet.Example: const char apn[] = "internet";2.GPS Parsing (NEO-6M):UART Serial.Initialize hardware serial for GPS (e.g., RX GPIO 16, TX GPIO 17) and parse valid NMEA coordinates using TinyGPS++ before sending requests.3.HTTP Client Request:Data Push.Use HTTPClient (or TinyGSM HTTP methods) to POST the JSON payload to /api/readings every set interval (e.g., every 10–30 seconds).4. VerificationConfirm Server Ingestion: Once your ESP32 issues an HTTP 200 or HTTP 201 response code on POST, check the dashboard at / or history log at /history.Real-time Check: The server will emit a reading:new Socket.io event upon receiving the payload, causing the web app dashboard to instantly update without requiring a browser refresh.
